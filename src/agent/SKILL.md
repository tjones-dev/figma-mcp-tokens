# Syncing design tokens from Figma

This project's design tokens are generated by `figma-mcp-tokens` from the Figma file named in
`__CONFIG__`. That file also says where the tokens and outputs are written (defaults:
`tokens/tokens.json`, `tokens/tokens.css`, `tokens/tokens.ts`).

- Don't read Figma variables any other way (`get_variable_defs`, `get_design_context`, your own
  `use_figma` code) to update tokens. The export script handles chunking, checksums, units and modes.
- Don't edit the generated files by hand. Change the design in Figma and sync, or change
  `tokens.json` and run `build`.

## Sync from Figma

1. Run `__CLI__ script`. It prints JavaScript for the Figma plugin sandbox.
2. Call the Figma MCP `use_figma` tool with that output, unchanged, as the code, and the file key
   from the `figma` URL in `__CONFIG__` (the script also contains it as `FILE_KEY`). Follow the
   Figma MCP server's own rules for `use_figma`, such as loading its figma-use skill first. The
   script only reads; it changes nothing in Figma.
3. Save the whole result object as JSON to the path in its `saveAs` field, relative to the folder
   `__CONFIG__` is in. Copy the `data` string character for character: it's checked against
   `checksum`, and a changed or truncated chunk is refused.
4. If the result's `chunks` is more than 1, do the same for each further chunk with
   `__CLI__ script --chunk <n>`. The result's `next` field says what comes next.
5. Run `__CLI__ sync`. It prints the files it wrote, or `No changes.`. Tell the user which.

## Other changes

- After changing `__CONFIG__` or editing `tokens.json`, run `__CLI__ build`. The exception is
  `merge` in `__CONFIG__`, which lists tier collections to combine into one merged collection:
  only `sync` applies it, so after changing `merge`, export from Figma and sync.
- Run `__CLI__ --help` for the commands.

## When it fails

- **"Chunk N's checksum doesn't match"**: export that chunk again and save it exactly as returned.
- **"Missing chunk N of M"**: export and save the missing chunks, then sync again.
- **"The chunks … come from different exports"**: the Figma file changed between chunks. Delete
  the dump folder (the folder in `saveAs`) and export every chunk again.
- **"This is file X; the config expects Y"**: the wrong file was used. Check the file key you
  passed to `use_figma`.
- **"N problems: …"**: things the tool can't express. Show the list to the user; they fix them in
  Figma or decide to set `"strict": false`. Don't change `strict` yourself. Problems starting
  with `Merge <name>:` mean the tier collections in that merge disagree on a variable; the user
  fixes them in Figma.
- **"Merge Element: no collection named Element T2 in the Figma file."**: a tier collection listed
  under `merge` in `__CONFIG__` was renamed, deleted or misspelled. Tell the user which one. If
  they confirm the new name, update `merge` and sync again; otherwise they fix it in Figma.
  Fails even with `"strict": false`.
- **"Merge Element: mode fire is in both Element T1 and Element T2; rename one."**: each mode
  must be in only one tier. The user renames the mode in one tier in Figma; then export every
  chunk and sync again. Fails even with `"strict": false`.
- **"Warning: merge in the config doesn't match tokens.json (Element); export from Figma and run
  figma-mcp-tokens sync."** from `build`: `merge` changed since the last sync, so the outputs
  were built from the old merge. Do the full sync from Figma above, then tell the user.
